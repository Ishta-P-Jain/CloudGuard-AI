# CloudGuard AI - Student 3 Security And AI Guide

Role: security checks, risk scoring, Groq integration, AI explanations, AI remediation, PDF generation, and testing.

You are building the intelligence of CloudGuard AI. Your work decides what is risky, why it is risky, and how to fix it.

## 1. Your Role In Simple Words

Student 2 collects cloud resource data from Localstack. You write rules that inspect that data and detect security problems.

Then you use Groq AI to explain those problems in simple English.

Analogy: If CloudGuard AI is a doctor, Student 2 collects test results, and you diagnose the illness and explain the treatment.

If your part does not exist, the project becomes a simple resource viewer instead of a security auditor.

## 2. Concepts You Must Understand First

### Cybersecurity

What it is: Protecting systems, data, and users from attacks.

Why we need it: Cloud systems can be misconfigured and exposed to attackers.

Problem it solves: It reduces the chance of data leaks and system compromise.

How it fits: CloudGuard AI finds risky cloud settings.

Analogy: Cybersecurity is like locking doors and checking windows before leaving home.

If we do not use it: Cloud resources may be publicly exposed.

### Cloud Security Misconfiguration

What it is: A wrong or unsafe cloud setting.

Why we need to detect it: Many breaches happen because of simple mistakes.

Problem it solves: It warns users before attackers exploit the issue.

How it fits: Your rules detect misconfigurations in S3, IAM, and EC2.

Analogy: Leaving your front door open is a home misconfiguration.

If we do not detect it: The demo has no real security value.

### Rule Engine

What it is: A system that runs many checks on data.

Why we need it: We need a clean way to add security checks.

Problem it solves: It avoids writing all checks in one messy file.

How it fits: Each CloudGuard AI rule checks one type of problem.

Analogy: An exam checker uses answer keys. A rule engine uses security rules.

If we do not use it: The code becomes hard to maintain.

### Risk Score

What it is: A number that shows how safe or unsafe the environment is.

Why we need it: Reviewers and users need a quick summary.

Problem it solves: It converts many findings into one understandable score.

How it fits: CloudGuard AI shows a score out of 100.

Analogy: A health score tells you general fitness without reading every medical report.

If we do not use it: Users must inspect every finding manually.

### AI Explanation

What it is: A plain-English explanation generated by an AI model.

Why we need it: Beginners may not understand security findings.

Problem it solves: It turns technical findings into learning-friendly guidance.

How it fits: Groq explains each finding when the user clicks "Explain & Fix".

Analogy: A teacher explains why an answer is wrong and how to correct it.

If we do not use it: The project becomes only rule-based and less impressive.

### Prompt

What it is: The instruction text sent to an AI model.

Why we need it: AI needs clear instructions to return useful output.

Problem it solves: It controls the style and structure of AI responses.

How it fits: You write prompts that ask Groq for explanation, danger, impact, and remediation steps.

Analogy: A prompt is like an exam question. Better questions get better answers.

If we do not write good prompts: AI output may be vague or unusable.

## 7. Risk Scoring

Use simple severity points:

| Severity | Points |
|---|---:|
| Critical | 25 |
| High | 15 |
| Medium | 8 |
| Low | 3 |

Formula:

```text
security_score = max(0, 100 - total_risk_points)
```

Example:

```text
1 Critical = 25 points
2 High = 30 points
1 Medium = 8 points
Total risk = 63
Security score = 37
```

Why simple scoring is good:

- Easy to explain in viva
- Easy to implement
- Good visual dashboard value

### Function Interface Student 2 Will Call

Define this function in `services/risk_service.py`. Student 2 will call it immediately after `run_scan()`.

```python
def calculate_score(findings: list) -> dict:
    """
    Accepts the list of findings returned by run_scan().
    Returns a dict with the score and severity counts.

    Return shape:
    {
        "score": 37,
        "summary": {
            "total": 4,
            "critical": 1,
            "high": 2,
            "medium": 1,
            "low": 0
        }
    }
    """
```

Example usage in Student 2's code:

```python
from services.risk_service import calculate_score

result = calculate_score(findings)
score = result["score"]
summary = result["summary"]
```

Keep the return shape exactly as shown. Student 1's dashboard reads `score` and `summary` fields directly from the scan response.

def explain_finding(finding: dict) -> dict:

def generate_pdf(scan_id: str, score: int, summary: dict, findings: list) -> bytes:

## 14. Viva Answers For Student 3

Question: How does the security scanner work?

Answer: The backend collects resource data from Localstack, then the rule engine runs checks for risky settings such as public S3 access, open SSH, and overly permissive IAM policies.

Question: How does AI work?

Answer: When a user clicks Explain & Fix, we send the finding details to Groq. Groq returns a simple explanation, danger, impact, and remediation steps. We cache the response in PostgreSQL.

Question: Why not generate AI for every finding automatically?

Answer: To reduce cost, avoid delays, and prevent duplicate AI requests.

Question: What is risk scoring?

Answer: Each severity has points. We subtract total risk points from 100 to get a simple security score.
